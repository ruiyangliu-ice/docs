## Descripción general

Esta guía está dirigida a desarrolladores que integran dispositivos de cámara. Cubre las API de Camera SDK para los productos de las series M4, M4 Mega, M4 Pro, V1 Pro, S2, S2 Max y H3. El SDK se ejecuta en sistemas Windows x86 y Linux x86 o Arm.

Camera SDK proporciona API unificadas para acceder a dispositivos y configurar parámetros. Admite la adquisición síncrona y asíncrona de datos de profundidad, intensidad, nube de puntos y RGB. Algunos modelos de cámara también proporcionan datos de prevención de obstáculos, acoplamiento o localización.

<Info>
  Los ejemplos y las descripciones de las API se basan en la versión del SDK incluida con el producto. Los parámetros disponibles pueden variar según el producto, el firmware y la versión del SDK.
</Info>

Los ejemplos sirven como orientación para el desarrollo y pueden no cubrir todos los dispositivos o casos de uso.

## Configuración del entorno

### Configuración recomendada del host

| Elemento de configuración | Configuración recomendada |
| --- | --- |
| Sistema operativo | Windows 7, Windows 10 o Windows 11; Ubuntu 16.04 o posterior |
| Memoria | 4 GB o más |
| CPU | Cortex-A57 de cuatro núcleos o equivalente y superior |
| Adaptador de red | Ethernet Gigabit o superior |

### Conectar e instalar

#### Conexión del hardware

La cámara se conecta a una fuente externa de 24 V y al ordenador host donde se encuentra el host mediante un cable de red, como se muestra en la figura 2.1.

#### Configuración de red

1. El segmento de red IP predeterminado de la cámara es: 192.168.100.\*
2. En el ordenador host, configura la dirección IP del puerto de red conectado a la cámara con una dirección del segmento de red 192.168.100.x y asegúrate de que no entre en conflicto con el dispositivo. La máscara de subred es 255.255.255.0, como se muestra en la figura siguiente:

<Frame>
  ![Ilustraciones relacionadas con la construcción del entorno de red](/images/developers/camera-sdk-user-guide-network-environment-construction.avif)
</Frame>

3. Al conectarte a la cámara, se recomienda desactivar el firewall para evitar que el host donde se encuentra el SDK intercepte los paquetes de datos de la cámara, como se muestra en la figura siguiente:

<Frame>
  ![Ilustraciones relacionadas con la construcción del entorno de red 2](/images/developers/camera-sdk-user-guide-network-environment-construction-2.avif)
</Frame>

4. La configuración de red de Linux es la misma que la de Windows. Los comandos del firewall varían según la distribución. En Ubuntu, ejecuta:

```bash
sudo systemctl stop ufw.service
sudo systemctl disable ufw.service
sudo ufw status
```

##### Linux

1. Descomprime el paquete y ejecuta el script de instalación:

```bash
tar xvf Lanxin-MRDVS-xxx.tar.gz
cd Lanxin-MRDVS
sudo su root
chmod +x install.sh
./install.sh
```

El script de instalación instala el SDK en `/opt/Lanxin-MRDVS` y configura las variables de entorno para el usuario actual. Si el programa se ejecuta con otro usuario, vuelve a ejecutar el script para ese usuario o añade la siguiente línea al archivo `~/.bashrc` de dicho usuario:

```bash
export LD_LIBRARY_PATH=/opt/Lanxin-MRDVS/lib/:$LD_LIBRARY_PATH
```

Para las sesiones de terminal que estaban abiertas antes de la instalación, ejecuta el siguiente comando antes de iniciar el programa:

```bash
source ~/.bashrc
```

## Requisitos de las llamadas

### Tipos de parámetros y API correspondientes

1. Para los tipos enumerados con el prefijo LX\_INT, usa DcSetIntValue o DcGetIntValue para establecer u obtener parámetros de tipo INT;
2. Para los tipos enumerados con el prefijo LX\_FLOAT, usa DcSetFloatValue o DcGetFloatValue para establecer u obtener parámetros de tipo FLOAT;
3. Para los tipos enumerados con el prefijo LX\_BOOL, usa DcSetBoolValue o DcGetBoolValue para establecer u obtener parámetros de tipo BOOL;
4. Para los tipos enumerados con el prefijo LX\_STRING, usa DcSetStringValue o DcGetStringValue para establecer u obtener parámetros de tipo string;
5. Usa DcSetCmd para ejecutar instrucciones de los tipos enumerados con el prefijo LX\_CMD;
6. Para los tipos enumerados con el prefijo LX\_PTR, usa DcGetPtrValue para obtener resultados de tipo puntero;

### Condiciones previas de las API

<Warning>
  Cuando la transmisión está activa o cuando `LX_INT_WORK_MODE` está establecido en el modo siempre activado, no establezcas las funciones que se indican a continuación.
</Warning>

**1. Cuando se inicia el flujo o el modo de funcionamiento (LX\_INT\_WORK\_MODE) es el modo normalmente abierto, no se permite establecer las siguientes funciones:**

- DcSetRoi
- LX\_INT\_3D\_BINNING\_MODE;
- LX\_INT\_2D\_BINNING\_MODE;
- LX\_BOOL\_ENABLE\_2D\_TO\_DEPTH;
- LX\_BOOL\_ENABLE\_MULTI\_EXPOSURE\_HDR;
- LX\_BOOL\_ENABLE\_MULTI\_MACHINE;
- LX\_INT\_TRIGGER\_MODE;
- LX\_INT\_CALCULATE\_UP;
- LX\_BOOL\_ENABLE\_HDR;
- LX\_BOOL\_ENABLE\_TOF\_DEPTH\_CALIBE;
- LX\_BOOL\_ENABLE\_SYNC\_FRAME
- LX\_INT\_SAVE\_PARAMS\_GROUP

**2. No se permite establecer parámetros aunque el modo de funcionamiento (LX\_INT\_WORK\_MODE) sea normalmente abierto:**

- LX\_INT\_TOF\_FREQMODE<br />

**3. Cuando la exposición automática 3D (LX\_BOOL\_ENABLE\_3D\_AUTO\_EXPOSURE) está activada, no se permiten las siguientes operaciones de enumeración de funciones:**

- LX\_BOOL\_ENABLE\_MULTI\_EXPOSURE\_HDR ;
- LX\_INT\_FIRST\_EXPOSURE;
- LX\_INT\_SECOND\_EXPOSURE;
- LX\_INT\_THIRD\_EXPOSURE;
- LX\_INT\_GAIN;<br />

**4. Cuando la exposición automática 3D (LX\_BOOL\_ENABLE\_3D\_AUTO\_EXPOSURE) está desactivada, no se permite operar la siguiente enumeración de funciones:**

- LX\_INT\_3D\_AUTO\_EXPOSURE\_LEVEL

No se permite establecer el valor máximo de exposición automática 3D (LX\_INT\_3D\_AUTO\_EXPOSURE\_MAX) ni el valor mínimo

- (LX\_INT\_3D\_AUTO\_EXPOSURE\_MIN)

**5. Cuando la exposición automática 2D (LX\_BOOL\_ENABLE\_2D\_AUTO\_EXPOSURE) está activada, no se permiten las siguientes operaciones de enumeración de funciones:**

- LX\_INT\_2D\_MANUAL\_EXPOSURE

<br />**6. Cuando la exposición automática 2D (LX\_BOOL\_ENABLE\_2D\_AUTO\_EXPOSURE) está desactivada, no se permite operar la siguiente enumeración de funciones:**

- LX\_INT\_2D\_AUTO\_EXPOSURE\_LEVEL;

<br />7.**En el modo de filtrado extraordinario, no se permiten las siguientes configuraciones:**

- LX\_INT\_FILTER\_SMOOTH\_LEVEL LX\_INT\_FILTER\_NOISE\_LEVEL
- LX\_INT\_FILTER\_TIME\_LEVEL

<br />8.**Al activar la corrección de distorsión 2D, primero se debe activar la alineación RGB-D:**

- LX\_BOOL\_ENABLE\_2D\_TO\_DEPTH

<br />9.**Para dispositivos que no sean de tipo S2, al activar el algoritmo integrado primero debes establecer el algoritmo ToF. Los parámetros del algoritmo solo se pueden establecer cuando el algoritmo integrado (LX\_INT\_ALGORITHM\_MODE) está activado.**

- (LX\_STRING\_ALGORITHM\_PARAMS)

<br />10.**Para obtener datos de nube de puntos (LX\_PTR\_XYZ\_DATA), primero debes abrir el mapa de profundidad**

- (LX\_BOOL\_ENABLE\_3D\_DEPTH\_STREAM)

## Tipos de datos

### 5.1 LX\_STATE

Función: código de estado del valor devuelto por la interfaz del SDK

| Palabras clave | Descripción |
| --- | --- |
| LX\_SUCCESS | Ejecución correcta de la función |
| LX\_ERROR | Error en la ejecución de la función |
| LX\_E\_NOT\_SUPPORT | La cámara conectada no admite esta función |
| LX\_E\_NETWORK\_ERROR | Error de comunicación de red |
| LX\_E\_INPUT\_ILLEGAL | Se han pasado parámetros de función no válidos |

| LX\_E\_DEVICE\_ERROR | Fallo del equipo |
| LX\_E\_DEVICE\_NEED\_UPDATE | La versión del dispositivo es demasiado baja y es necesario actualizar la versión del firmware |
| LX\_E\_API\_NEED\_UPDATE | La versión de la API es demasiado baja y es necesario actualizar el SDK |
| LX\_E\_CTRL\_PERMISS\_ERROR | Error en el permiso de control exclusivo (el dispositivo solo puede tener una conexión de SDK al mismo tiempo) |
| LX\_E\_GET\_DEVICEINFO\_ERROR | No se ha podido obtener la información del dispositivo |
| LX\_E\_IMAGE\_SIZE\_ERROR | El tamaño de la imagen no coincide; vuelve a abrir la cámara |
| LX\_E\_IMAGE\_PARTITION\_ERROR | Error al analizar la imagen |
| LX\_E\_DEVICE\_NOT\_CONNECTED | La cámara no está conectada |
| LX\_E\_DEVICE\_INIT\_FAILED | Error al inicializar la cámara |
| LX\_E\_DEVICE\_NOT\_FOUND | No se ha encontrado ninguna cámara coincidente |
| LX\_E\_FILE\_INVALID | Error de archivo (nombre, tipo o formato incorrecto) |
| LX\_E\_CRC\_CHECK\_FAILED | Error en la verificación CRC o MD5 del archivo |
| LX\_E\_TIME\_OUT | Tiempo de espera agotado |
| LX\_E\_FRAME\_LOSS | Falta un fotograma |
| LX\_E\_ENABLE\_ANYSTREAM\_FAILED | No se ha podido abrir ninguna transmisión |
| LX\_E\_NOT\_RECEIVE\_STREAM | No se han recibido datos de transmisión |

### 6.7 Establecer la IP de la cámara

#### 6.7.1 DcSetCameraIp

**Prototipo de la función:**

<Frame>
  ![Iconos relacionados con DcSetCameraIp](/images/developers/camera-sdk-user-guide-dcsetcameraip.avif)
</Frame>

**Función:**

Establece la IP de la cámara, la máscara de subred y la puerta de enlace.

**Parámetros de la función:**

- \[in\]handle identificador del dispositivo,
- \[in\]ip IP del dispositivo,
- \[in\]netmask máscara de subred (si está vacía, el valor predeterminado interno es "255.255.0.0")
- \[in\]gateway IP de la puerta de enlace (si está vacía, el valor predeterminado interno establece como puerta de enlace el último segmento de red de ip en "1")

**Valor devuelto:**

Datos de tipo Int; este valor es igual a LX\_SUCCESS, lo que indica que la llamada a la interfaz se ha realizado correctamente.

**Nota:** Cuando el dispositivo no está conectado, primero debes obtenerlo mediante una búsqueda. Si el dispositivo admite modificar la puerta de enlace y la máscara de subred, establece la puerta de enlace en el mismo segmento de red y la máscara de subred en "255.255.0.0". Después de la modificación, la lista de dispositivos cambiará y debes volver a llamar a la interfaz DcGetDeviceList para obtener la nueva lista de dispositivos.

### 6.6 Establecer la ROI y la ruta de parámetros

#### 6.6.1 DcSetRoI

**Prototipo de la función:**

<Frame>
  ![Iconos relacionados con DcSetRoI](/images/developers/camera-sdk-user-guide-dcsetroi.avif)
</Frame>

**Función:**

Establece el área de la ROI. Si el valor de entrada no es un múltiplo entero de 8, se procesa automáticamente de forma interna como el múltiplo entero de 8 más cercano al valor de destino. Los parámetros del tamaño de la imagen deben actualizarse después de establecerla.

**Parámetros de la función:**

- \[in\]handle identificador del dispositivo
- \[in\]offsetx desplazamiento horizontal del punto inicial en píxeles
- \[in\]offsety desplazamiento vertical del punto inicial en píxeles
- \[in\]widthroi ancho del área de destino
- \[in\]heightroi alto del área de destino
- \[in\]type0: imagen 3D; 1: imagen 2D

**Valor devuelto:**

Datos de tipo Int; este valor es igual a LX\_SUCCESS, lo que indica que la llamada a la interfaz se ha realizado correctamente.

**Nota:** Asegúrate de que los parámetros que se pasan sean válidos.
