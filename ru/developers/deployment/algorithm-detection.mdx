Это руководство посвящено развертыванию, калибровке, настройке и интеграции результатов алгоритмов MRDVS для обнаружения людей, мест хранения и объема. Алгоритм работает на камере; хост-приложение алгоритма используется для настройки, обновления и проверки результатов.

<Info>
  Прошивка алгоритма и хост-приложение алгоритма поставляются для каждого проекта отдельно. Перед прошивкой алгоритма убедитесь, что на камере установлена прошивка MDS. Получите установочный пакет, соответствующий проекту и модели камеры.
</Info>

## Поддерживаемая область

### Компоненты системы

| Компонент | Функция |
| --- | --- |
| 3D-камера | Захватывает RGB-изображения и облака точек и запускает алгоритм обнаружения на камере. |
| Хост-приложение алгоритма | Настраивает алгоритмы, калибрует внешние параметры, отображает результаты и обновляет прошивку алгоритма. |
| Промышленный ПК или система верхнего уровня | Запускает хост-приложение или считывает результаты через сетевой интерфейс. |
| LiDAR | `mid360`, используется в исходной конфигурации решения на основе радара. |

### Алгоритмы и камеры

| Алгоритм | Поддерживаемая камера |
| --- | --- |
| Обнаружение людей | M4 Pro |
| Обнаружение мест хранения | S10 Pro |
| Измерение объема | S10 и S10 Pro |

Информацию о продукте см. на [странице 3D-камеры S10](/ru/products/s-series/s10-overview).

## Развертывание оборудования и сети

### Установка камеры

Используйте жесткий кронштейн, чтобы после установки предотвратить смещение или вибрацию. Для обнаружения людей обычно используется горизонтальная установка или установка с углом не более 30°.

<Frame>
  ![Примеры установки кронштейна камеры](/images/developers/deployment-algorithm-detection-camera-installation-methods.avif)
</Frame>

### Подключение устройств

<Steps>
  <Step title="Подключите питание и сеть">
    Питайте камеру стабилизированным источником `24 V DC`. Подключите камеру к гигабитному коммутатору или контроллеру кабелем Cat6A или Cat7.
  </Step>
  <Step title="Разверните несколько камер">
    Установите каждую камеру на высоте и в положении, указанными в плане CAD. Подключите все камеры через гигабитный коммутатор и проверьте питание и состояние соединения каждой камеры.
  </Step>
  <Step title="Подготовьте тестовые объекты">
    До калибровки внешних параметров и настройки зон поместите в поле зрения камеры людей, паллеты или товары, которые должны обнаруживаться.
  </Step>
</Steps>

### Настройка сети хоста

Поместите хост-компьютер и камеру в одну подсеть. В исходном примере используется следующая схема:

| Параметр | Пример |
| --- | --- |
| IP-адрес хоста | `192.168.100.xxx` |
| Маска подсети | `255.255.255.0` |
| Шлюз по умолчанию | `192.168.100.1` |

<Steps>
  <Step title="Откройте настройки адаптера">
    В Windows откройте **Control Panel → Network and Sharing Center → Change adapter settings**, затем выберите Ethernet-адаптер, подключенный к камере.
  </Step>
  <Step title="Настройте IPv4">
    Откройте **Internet Protocol Version 4 (TCP/IPv4)**, выберите **Use the following IP address** и введите свободный статический адрес в подсети камеры.
  </Step>
  <Step title="Проверьте соединение">
    Сохраните настройки, убедитесь в наличии гигабитного соединения и используйте хост-приложение для поиска или открытия камеры.
  </Step>
</Steps>

<Columns cols={2}>
  <Frame>
    ![Центр управления сетями и общим доступом Windows](/images/developers/deployment-algorithm-detection-camera-network-configuration.avif)
  </Frame>

  <Frame>
    ![Настройки статического IPv4-адреса Windows](/images/developers/deployment-algorithm-detection-camera-network-configuration-7.avif)
  </Frame>

<Warning>
  Не оставляйте брандмауэр отключенным в производственной сети. Если хост-приложение не может подключиться, сначала создайте правило для нужного приложения или порта. Временно отключайте брандмауэр только в доверенной сети отладки, затем восстановите защиту.
</Warning>

## Установка и обновление программного обеспечения

### Установка хост-приложений

1. Получите хост-приложение камеры на странице [загрузки ПО](https://zcnt5g3o2989.feishu.cn/wiki/Q8IYwGiGaiIvIyktiavczymanOe?from=from_copylink "Загрузка ПО").
2. Установите хост-приложение камеры не на системный диск.
3. Скопируйте поставленные для проекта файлы хост-приложения алгоритма в папку `Tools` каталога хост-приложения камеры. Замените файлы с совпадающими именами, затем дважды щелкните исполняемый файл для запуска.

<Frame>
  ![Установка хост-приложения камеры](/images/developers/deployment-algorithm-detection-picture-2.avif)
</Frame>

Чтобы обновить только хост-приложение алгоритма, замените его файл `.exe` поставленной версией.

### Обновление прошивки алгоритма

<Warning>
  Во время прошивки камера перезапускается. Не отключайте питание или сеть и не закрывайте хост-приложение. Пакет должен соответствовать модели камеры, версии прошивки MDS и алгоритму проекта.
</Warning>

<Tabs>
  <Tab title="Хост-приложение камеры">
    1. Запустите `LxCameraViewer.exe` и откройте камеру.
    2. Выберите **Basic tools → Function settings → Firmware upgrade**.
    3. Выберите поставленный файл алгоритма обнаружения и нажмите **Run**.
  </Tab>
  <Tab title="Хост-приложение алгоритма">
    1. Выберите целевую камеру в списке устройств.
    2. Выберите **Upgrade firmware**, укажите файл алгоритма обнаружения и откройте его.
    3. Дождитесь повторного появления камеры в списке устройств.
  </Tab>
</Tabs>

После перезапуска, когда камера снова появится, прошивка завершена. Зеленый фон камеры в хост-приложении алгоритма означает, что камера подключена и алгоритм доступен.

## Хост-приложение алгоритма

### Запуск и состояние

Запустите `LxApplicationViewer.exe`. Зеленый значок в списке устройств означает, что камера подключена. Выберите устройство, чтобы переключить текущий вид между режимом RGB и режимом облака точек. Обычные пользователи могут просматривать результаты; администраторы могут изменять параметры камеры и алгоритма.

<Frame>
  ![Главное окно хост-приложения алгоритма](/images/developers/deployment-algorithm-detection-administrator.avif)
</Frame>

### Основные инструменты

| Функция | Описание |
| --- | --- |
| Переключение пользователя | Переключение уровней разрешений. Администраторы могут настраивать параметры камеры и алгоритма. |
| Идеальная поверхность | Показать или скрыть опорную горизонтальную плоскость. |
| Поверхность внешних параметров | Показать или скрыть поверхность, рассчитанную по калибровке внешних параметров. |
| Кэш отображения | Не изменяйте. |
| Отображение алгоритма | Показать включенный в данный момент алгоритм. |
| Экспорт сохраненных изображений | Экспортировать сохраненные изображения. |
| Историческое воспроизведение | Просматривать RGB-изображения и журналы данных ToF. |
| Переключение алгоритма приложения | Выбрать запускаемый алгоритм, затем нажать **Save and send**. |
| Отображение результатов обнаружения | Показать выходные данные текущего алгоритма. |

### Строка состояния и воспроизведение

| Функция | Описание |
| --- | --- |
| RGB | Показать RGB-изображение. |
| Облако точек | Показать облако точек. |
| Остановить алгоритм | Остановить текущий алгоритм. Он не запустится автоматически, пока камера снова не будет включена. |
| Обновить прошивку | Открыть рабочий процесс обновления прошивки алгоритма. |
| Перезапустить камеру | Перезапустить выбранную камеру. |

При изменении состояния программа сохраняет один RGB-кадр и данные облака точек. Данные воспроизведения не являются общими для разных алгоритмов. Время воспроизведения использует внутренние часы камеры, а не системное время хост-компьютера.

Если фон устройства желтый или он зеленый, но изображение не обновляется, включите автоматическое обновление, чтобы возобновить получение изображений.

## Калибровка внешних параметров

### Конфигурация камеры

| Параметр | Описание |
| --- | --- |
| Camera name | Идентифицирует камеру при развертывании нескольких камер. |
| Simulation mode | Внутренняя функция; оставьте отключенной. |
| Image-save mode | Сохраняет данные изображений алгоритма на камере. |
| Image-acquisition mode | `MDS` не занимает доступ к камере. `SDK` занимает его; хост-приложение не может открыть камеру во время работы алгоритма. |
| `x`, `y`, `z` | Положение камеры во внешних параметрах; `z` — высота камеры над землей. |
| `roll`, `pitch`, `yaw` | Углы ориентации камеры во внешних параметрах. |
| Ideal ground | Сохраняйте значение по умолчанию. |
| Read configuration from camera | Считывает текущую конфигурацию камеры. |
| Save and send | Записывает изменения в камеру. Несохраненные параметры не применяются. |
| Extrinsic calibration | Калибрует высоту и ориентацию камеры. |

<Tabs>
  <Tab title="Вертикальная установка">
    1. Откройте **Camera configuration**. Перед калибровкой задайте `x`, `y`, `z`, `roll`, `pitch` и `yaw` равными `0`, затем выберите **Save and send**.
    2. Выберите **Extrinsic calibration**. После успешной калибровки проверьте результат на панели параметров.

    <Frame>
      ![Калибровка внешних параметров при вертикальной установке](/images/developers/deployment-algorithm-detection-vertical-installation-of-external-parameter-calibration.avif)
    </Frame>
  </Tab>
  <Tab title="Горизонтальная установка">
    1. Откройте **Camera configuration** и перейдите на страницу калибровки параметров.
    2. Совместите поверхность облака точек с системой координат: красная ось `X` и зеленая ось `Y` лежат на земле, а синяя ось `Z` перпендикулярна земле и направлена вверх.
    3. Обычно сначала настраивайте только `roll` и `z`, а остальные значения задайте равными `0`. После проверки выберите **Save and send**.

    <Frame>
      ![Результат калибровки внешних параметров при горизонтальной установке](/images/developers/deployment-algorithm-detection-1.avif)
    </Frame>
  </Tab>
</Tabs>

## Развертывание алгоритма

Переключитесь в режим облака точек и прокрутите область изображения, чтобы отобразить данные облака точек.

### Обнаружение людей

<Steps>
  <Step title="Откалибруйте горизонтальную установку">
    Совместите оси `X` и `Y` с облаком точек земли. Ось `Z` должна быть перпендикулярна земле и направлена вверх.
  </Step>
  <Step title="Задайте глобальные параметры">
    Откройте **Human detection**. Обычно требуется задать только **Rotation detection**. Поворот камеры по часовой стрелке поддерживает `0°`, `90°`, `180°` и `270°`.
  </Step>
  <Step title="Создайте зону обнаружения">
    Выберите **Add detection region**, задайте минимальные и максимальные `X`, `Y` и `Z` и переместите зону на объект. В исходном примере используется зона размером `1000 × 1000 × 2000 mm`.
  </Step>
  <Step title="Сохраните и проверьте результат">
    Выберите **Save and send**, выполните тест прохода человека через зону и проверьте результат в строке состояния или историческом воспроизведении.
  </Step>
</Steps>

| Правило сопоставления | Нет человека | Человек | Препятствие | Человек и препятствие |
| --- | --- | --- | --- | --- |
| Только глубина | `0` | `2` | `2` | `2` |
| Семантика и глубина | `0` | `1` | `0` | `1` |

Режим только глубины сообщает обо всех объектах в зоне. Режим семантики и глубины сообщает только о кластерах, классифицированных как люди.

### Обнаружение мест хранения

<Steps>
  <Step title="Откалибруйте камеру">
    Выполните процедуру калибровки внешних параметров. Совместите `X` и `Y` с землей, а `Z` оставьте перпендикулярной и направленной вверх.
  </Step>
  <Step title="Настройте глобальные параметры">
    Задайте **Alignment check**, **Alignment angle** и **Minimum point count** для объекта. Включите проверку выравнивания, если груз должен размещаться под заданным углом.
  </Step>
  <Step title="Создайте места хранения">
    В режиме облака точек выберите **Add storage location**, переключитесь на вид сверху и нажмите `X`, чтобы начать или завершить рисование. Перетащите прямоугольник на паллету и настройте границы `X`, `Y` и `Z`. Нажмите `X` еще раз, чтобы выйти из режима рисования.
  </Step>
  <Step title="Сохраните и проверьте результат">
    Выберите **Save and send**. Настройте места в режиме 2D RGB или трехмерного облака точек и проверьте `Result` в строке состояния.
  </Step>
</Steps>

  ![Рисование зоны места хранения в режиме облака точек](/images/developers/deployment-algorithm-detection-point-cloud-mode-location-setting-4.avif)

| Состояние места хранения | `Result` |
| --- | --- |
| Пусто | `0` |
| Занято или занято и выровнено | `1` |
| Занято, угол превышает порог выравнивания | `2` |
| Занято и находится за пределами границ места | `3` |

Для регулярной компоновки используйте **Copy current box**, чтобы создать места с фиксированными направлением и интервалом. Если требуется проверка с QR-кодом, используйте **QR Code calibration** для настройки размеров места и диапазона глубины.

### Измерение объема

<Steps>
  <Step title="Откалибруйте вертикальную установку">
    Измерение объема выполняется сверху вниз. После калибровки ось `Z` направлена вниз, а плоскость `X`/`Y` параллельна земле.
  </Step>
  <Step title="Задайте плоскость обнаружения">
    Для грузов, размещенных непосредственно на полу, задайте плоскость обнаружения на высоте пола. Чтобы измерять только грузы на паллете, совместите плоскость с облаком точек паллеты.
  </Step>
  <Step title="Задайте минимальные размеры и зону">
    Задайте минимальные значения `X`, `Y` и `Z`, чтобы отфильтровать небольшие объекты. Затем задайте границы зоны с учетом плоскости обнаружения и размеров груза.
  </Step>
  <Step title="Сохраните и проверьте результат">
    Выберите **Save and send**, поместите один или несколько объектов в зону и проверьте возвращенные длину, ширину, высоту и количество.
  </Step>
</Steps>

## Интерфейсы связи

<Note>
  IP-адрес в примерах приведен только для иллюстрации. Замените его адресом камеры на объекте, затем перед интеграцией с системой верхнего уровня проверьте сеть, состояние алгоритма и формат результатов.
</Note>

### Способы передачи

| Протокол | Порт | Запрос | Назначение |
| --- | --- | --- | --- |
| TCP | `14951` | `RESULT_UPDATE` | Получить текущий результат алгоритма. |
| UDP | `14950` | `RESULT_UPDATE` | Получить текущий результат алгоритма. |
| HTTP | `14952` | `RESULT_UPDATE` | Получить результат алгоритма в формате JSON. |
| TCP / UDP | Порт результатов | `TM_TRIGGER` | Выполнить однократное измерение объема по запуску и вернуть результат. |
| Modbus TCP | `16502` | Считать регистры хранения | Считать состояние мест хранения. |

### Запрос результата HTTP

Система верхнего уровня отправляет запрос результата на конечную точку машинного зрения, которая возвращает строку JSON. Используйте в HTTP-клиенте заголовки запроса, поставленные для проекта, и следующее тело запроса.

<ParamField body="command" default="RESULT_UPDATE" type="string" required>

</ParamField>

### Modbus TCP (обнаружение мест хранения)

Результаты упорядочены по идентификатору места хранения; возвращаются не более первых 16 мест.

| Параметр | Значение |
| --- | --- |
| Порт | `16502` |
| Адрес прослушивания | `0.0.0.0` (все сетевые интерфейсы) |
| Количество регистров | `16` |
| Начальный адрес | `0x0100` |
| Порядок байтов | Big-endian |

| Регистр | Содержимое | Формат данных |
| --- | --- | --- |
| `0x0100 + ID` | Результаты обнаружения места хранения и маркера | 2-байтовый `uint16_t` |
| Старшие 8 бит | Код состояния места хранения | `0–2` |
| Младшие 8 бит | Код состояния маркера | `0–2`; функция в настоящее время недоступна, поэтому код имеет то же значение, что и код состояния места. |

| Состояние места | Значение | Условие |
| --- | --- | --- |
| `0` | Пусто | Нет товара или паллеты. |
| `1` | Занято нормально | Товар размещен в соответствии с требованиями. |
| `2` | Занято аномально | Размер или положение груза не соответствуют требованиям. |

| Состояние маркера | Значение |
| --- | --- |
| `0` | Маркер не обнаружен. |
| `1` | Маркер обнаружен. |
| `2` | Ошибка обнаружения маркера. |

#### Чтение четвертого места хранения

В следующем примере используется идентификатор транзакции `0x0001` для чтения одного регистра хранения по адресу `0x0104`. Ответ содержит состояние `0x0002`.

```text
Request: 00 01 00 00 00 06 FF 03 01 04 00 01
Response: 00 01 00 00 00 05 FF 03 02 00 02
```

| Поле | Значение запроса | Описание |
| --- | --- | --- |
| Идентификатор транзакции | `00 01` | Порядковый номер клиента; ответ должен ему соответствовать. |
| Идентификатор протокола | `00 00` | Фиксированное значение Modbus/TCP. |
| Длина | `00 06` | Количество байтов в следующих полях запроса. |
| Идентификатор устройства | `FF` | Режим широковещания или адрес устройства. |
| Код функции | `03` | Чтение регистров хранения. |
| Начальный адрес | `01 04` | `0x0100 + 4`. |
| Количество регистров | `00 01` | Чтение одного регистра. |

## Устранение неполадок

| Симптом | Приоритетные проверки |
| --- | --- |
| Камера не найдена | Убедитесь, что хост и камера находятся в одной подсети, сетевой адаптер работает на гигабитной скорости, а питание и соединения с коммутатором исправны. |
| Параметры не применяются | Убедитесь, что после изменения была выбрана команда **Save and send**. |
| Нет результата алгоритма | Убедитесь, что прошита правильная прошивка алгоритма, устройство отображается зеленым и алгоритм включен. |
| Пустое или устаревшее облако точек | Прокрутите область облака точек, чтобы отобразить данные; при необходимости включите автоматическое обновление. |
| Аномальные результаты места или объема | Повторно проверьте направления осей внешних параметров, плоскость обнаружения и границы зоны, затем повторите тест с объектами на месте. |
