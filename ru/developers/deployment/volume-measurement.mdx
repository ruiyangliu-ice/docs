Алгоритм измерения объема работает на камере и измеряет длину, ширину и высоту неподвижных или движущихся объектов. Для развертывания требуются жесткая установка, сетевое соединение, калибровка внешних параметров и настройка зоны обнаружения. Подключите несколько камер к одной сети через гигабитный коммутатор.

<Info>
  Это скрытое историческое руководство по развертыванию. Прошивка алгоритма и выделенное хост-приложение поставляются для каждого проекта отдельно. Перед развертыванием убедитесь, что версии камеры, прошивки и программного обеспечения совместимы.
</Info>

## Область применения

Этот рабочий процесс предназначен для проектов измерения объема в логистике, работе с посылками, на складах и с сыпучими материалами, использующих камеры M Series. Алгоритм измеряет один или несколько объектов в зоне обнаружения. Идентификацию объектов, сбор данных о весе и связь с бизнес-системой выполняет система верхнего уровня.

Информацию о продукте см. на странице [камер M Series ToF](/ru/products/m-series/overview "Камеры M Series ToF").

## Установка и подготовка системы

### Установка оборудования

- Используйте жесткий кронштейн для установки камеры M4 так, чтобы ее лицевая сторона была параллельна плоскости обнаружения и направлена на нее.
- Питайте камеру напряжением `24 VDC`. Подключите ее к хосту или гигабитному коммутатору кабелем Cat6A или Cat7.
- При использовании нескольких камер назначьте каждой уникальный сетевой адрес и проверьте состояние питания.

  ![Камера M4, установленная лицевой стороной вниз для измерения объема](/images/developers/deployment-volume-measurement-camera-installation-methods.avif)

### Требования к хосту

| Параметр | Рекомендуемая конфигурация |
| --- | --- |
| Операционная система | Windows 10 или более поздняя версия |
| ЦП | Intel® Core™ i5 (7-го поколения) или более поздняя версия |
| Память | 8 GB или больше |
| Графический процессор | Intel® UHD Graphics или более производительный встроенный или дискретный графический процессор |

Сначала установите [LxCameraViewer](/ru/developers/software/lxcameraviewer "Загрузка ПО"), затем поместите поставленное для проекта приложение измерения объема в каталог `Lanxin-MRDVS\\Tools`. Замените файлы согласно инструкциям поставки.

<Warning>
  Во время обновления прошивки камера перезапускается. Используйте только поставленный для проекта пакет алгоритма и перед обновлением создайте резервную копию проверенной конфигурации.
</Warning>

## Рабочий процесс развертывания

### 1. Настройка сети

Поместите хост и камеру в одну подсеть. В исходном примере развертывания используется следующая конфигурация:

| Параметр | Пример |
| --- | --- |
| IP-адрес хоста | `192.168.100.xxx` |
| Маска подсети | `255.255.255.0` |
| Шлюз по умолчанию | `192.168.100.1` |

В свойствах Ethernet-адаптера Windows выберите **Internet Protocol Version 4 (TCP/IPv4)** и задайте статический адрес. Разрешите приложению работу через правила брандмауэра отладочной сети; не отключайте производственный брандмауэр навсегда.

### 2. Калибровка внешних параметров

<Steps>
  <Step title="Восстановите состояние калибровки">
    Откройте **Camera configuration**. Убедитесь, что `x`, `y`, `z`, `roll`, `pitch` и `yaw` равны `0`. Если сохранены исторические значения, сбросьте их и выберите **Save and send**.
  </Step>
  <Step title="Выполните калибровку">
    Выберите **Extrinsic calibration**, подтвердите сообщение об успешном завершении и запишите полученное значение `z`.
  </Step>
  <Step title="Сохраните параметры положения">
    Снова задайте `z` равным `0` и выберите **Save and send**. В этом рабочем процессе фактическая высота камеры используется на следующем шаге как расстояние до плоскости обнаружения.
  </Step>
</Steps>

### 3. Задание плоскости и зоны обнаружения

В разделе **Volume detection** введите записанное значение `z` в поле **Detection-plane distance**, затем сохраните и отправьте его. Настройте границы зоны обнаружения в представлении облака точек:

| Параметр | Значение |
| --- | --- |
| Минимальный / максимальный X | Границы X прямоугольника обнаружения |
| Минимальный / максимальный Y | Границы Y прямоугольника обнаружения |
| Минимальный / максимальный Z | Границы Z прямоугольника обнаружения |

Расстояние до плоскости обнаружения задает опорный уровень пола; установите верхний предел Z немного выше этого расстояния. Нижний предел должен охватывать измеряемую высоту объектов. После настройки выберите **Save and send**.

### 4. Проверка результатов

Просматривайте состояние измерения объема в разделе **Basic tools**. Поместите объект в зону обнаружения и убедитесь, что его количество, длина, ширина и высота соответствуют условиям объекта. Для нескольких объектов переключайтесь между объемными блоками, чтобы проверить каждый результат.

Для измерения одним кадром включите **Trigger mode** в разделе **Volume detection**, сохраните конфигурацию и выберите **Single trigger** в разделе **Basic tools**, чтобы получить один кадр и результат.

## Основной интерфейс и параметры

### Параметры измерения объема

| Параметр | Описание |
| --- | --- |
| Trigger mode | Если включен, алгоритм выдает результаты только после запуска. |
| Upward detection | Инвертирует направление обнаружения; в стандартном рабочем процессе обнаружение выполняется вниз. |
| Detection frequency | Период обновления изображения и результата. |
| Detection-plane distance | Расстояние от камеры до плоскости обнаружения, в `mm`. |
| Neighborhood count / distance threshold | Параметры фильтрации облака точек; в большинстве случаев сохраняйте значения проекта по умолчанию. |
| Normal-vector filter / distance threshold | Параметры фильтрации границ и облака точек; перед изменением сохраните исходную конфигурацию. |
| Minimum point count | Минимальное количество точек, необходимое для действительного объекта. |
| Minimum X / Y / Z | Минимальные размеры обнаруживаемого объекта, в `mm`. |

### Конфигурация камеры

| Параметр | Описание |
| --- | --- |
| Camera name | Отличает камеры при развертывании нескольких камер. |
| Image-save mode | Сохраняет изображения алгоритма на камере. |
| Image-acquisition mode | `MDS` не занимает доступ к камере. `SDK` занимает его; хост-приложение не может открыть камеру во время работы алгоритма. |
| Extrinsics | `x`, `y`, `z`, `roll`, `pitch` и `yaw`. |
| Save and send | Записывает текущие внешние параметры и конфигурацию алгоритма в камеру. |

## Интерфейс результатов

TCP, UDP и HTTP используют команду `RESULT_UPDATE` для запроса результатов измерения объема.

| Протокол | Порт | Назначение |
| --- | --: | --- |
| TCP | `14951` | Запросить результат измерения объема |
| UDP | `14950` | Запросить результат измерения объема |
| HTTP | `14952` | Запросить результат измерения объема в формате JSON |

<ParamField body="command" default="RESULT_UPDATE" type="string" required>
  Запрашивает у камеры текущий результат измерения объема.
</ParamField>

Основные поля ответа HTTP:

<ResponseField name="IP" type="string" required>
  IP-адрес камеры, создавшей данные.
</ResponseField>

<ResponseField name="TM" type="object[]" required>
  Список обнаруженных объектов.
</ResponseField>

<ResponseField name="TM_DATA_TIME" type="string">
  Время получения данных об объеме.
</ResponseField>

<ResponseField name="TM_RES_TIME" type="string">
  Время выдачи результата.
</ResponseField>

<ResponseField name="nick_name" type="string">
  Имя камеры.
</ResponseField>

<ResponseField name="ret_code" type="integer" required>
  Код возврата; `0` означает успех.
</ResponseField>

Каждый объект `TM` может содержать:

<ResponseField name="angle" type="number">
  Угол блока объекта.
</ResponseField>

<ResponseField name="cx" type="number">
  Координата X центра объекта.
</ResponseField>

<ResponseField name="cy" type="number">
  Координата Y центра объекта.
</ResponseField>

<ResponseField name="cz" type="number">
  Координата Z центра объекта.
</ResponseField>

<ResponseField name="height" type="number">
  Высота объекта.
</ResponseField>

<ResponseField name="length" type="number">
  Длина объекта.
</ResponseField>

<ResponseField name="width" type="number">
  Ширина объекта.
</ResponseField>

<ResponseField name="valid" type="boolean">
  Действителен ли результат. `false` означает недостаточную уверенность.
</ResponseField>

## Устранение неполадок

| Симптом | Рекомендуемое действие |
| --- | --- |
| Представление облака точек пустое или его трудно проверить | Наведите указатель и перетащите мышь в области облака точек, затем убедитесь, что камера выдает данные. |
| После калибровки обнаружение выполняется неправильно | Убедитесь, что внешнее значение `z` сброшено в `0`, а записанная высота калибровки введена как расстояние до плоскости обнаружения. |
| Объекты не обнаруживаются | Проверьте границы зоны, минимальные размеры, минимальное количество точек и полностью ли объект попадает в поле зрения. |
| LxCameraViewer не может открыть камеру | Проверьте, выбран ли режим получения изображения `SDK`; он занимает доступ к камере. |
