3D 비주얼 장애물 회피는 카메라에서 대상 감지, 지면 보정 및 장애물 상태 출력을 수행합니다. 카메라 외부 파라미터와 영역을 구성한 후 장애물 회피 파라미터 그룹을 전환하고 호스트 애플리케이션, API 또는 지원되는 필드버스를 통해 결과를 읽을 수 있습니다.

<Info>
  이 가이드의 값은 구성 관계를 설명하기 위한 예시일 뿐입니다. 실제 값은 차량, 설치 위치 및 작업 영역에 따라 달라집니다. 구성을 전송하기 전에 현장에서 값을 검증하세요.
</Info>

## 배포 준비

### 카메라 설치

| 차량 유형 | 설치 지침 |
| --- | --- |
| 언더라이드 AMR | 카메라를 주행 방향의 전면에 장착하세요. 장착 구조물이 시야를 가리지 않아야 합니다. S10을 권장합니다. |
| 지게차 | 렌즈가 약 `30°–55°` 아래를 향하도록 마스트에 카메라를 장착하세요. 시야의 가장자리가 차량 전면에 닿아야 합니다. 가능하면 설치 높이를 `2 m` 이하로 유지하세요. S10을 권장합니다. |

### 카메라 연결

<Steps>
  <Step title="호스트 네트워크 구성">
    카메라의 출고 시 주소는 `192.168.100.82`입니다. 컴퓨터의 Ethernet 어댑터를 같은 서브넷으로 구성하세요.
  </Step>
  <Step title="연결 및 이미징 확인">
    **LxCameraViewer**를 열고 카메라를 검색하여 연 다음 depth map과 포인트 클라우드가 올바르게 표시되는지 확인하세요.
  </Step>
  <Step title="필요할 때 카메라 주소 변경">
    **Other tools → Network → IP configuration tool**에서 IP 주소를 변경하세요. 변경 후 카메라가 재시작됩니다. 카메라를 다른 서브넷으로 이동하면 컴퓨터의 Ethernet 주소도 업데이트하세요.
  </Step>
</Steps>

<Warning>
  프로덕션 네트워크에서 방화벽을 영구적으로 비활성화하지 마세요. 제어된 디버깅 네트워크에서는 보안 정책에 따라 필요한 애플리케이션과 포트만 허용하세요.
</Warning>

### 이미징 조정

**3D settings** 및 **Filter settings**에서 이미지 품질을 확인하세요. 기존 장애물 회피 구성에서는 높은 노출 값 `650`, 낮은 노출 값 `200`, 낮은 신호 임계값 `10–20`을 시작점으로 사용할 수 있습니다. S10은 일반적으로 glare level `1`만 필요합니다. 표준이 아닌 설치에서는 배포 전에 기술 지원팀과 설정을 확인하세요.

## 장애물 회피 알고리즘 구성

<Steps>
  <Step title="알고리즘 활성화">
    **Application algorithm**에서 항상 켜짐 모드를 선택하세요. S10에서는 **Obstacle avoidance algorithm**을 선택하고, 그 밖의 지원 모델에서는 **Obstacle avoidance algorithm 2.0**을 선택하세요.
  </Step>
  <Step title="영역 유형 선택">
    차량에 사용할 직사각형 또는 섹터형 영역을 선택하세요. S10은 섹터형 영역을 지원하지 않으므로 사용하면 잘못된 결과가 발생할 수 있습니다.
  </Step>
  <Step title="외부 파라미터 및 영역 설정">
    먼저 카메라 외부 파라미터를 설정한 다음 장애물 회피 영역을 구성하세요. 외부 파라미터를 변경하면 다른 영역에서 새 값을 사용합니다.
  </Step>
  <Step title="전송 및 확인">
    파라미터를 전송한 다음 포인트 클라우드 보기와 출력 상태에서 경고, 알람 및 차폐 영역을 확인하세요.
  </Step>
</Steps>

### 카메라 외부 파라미터

| 파라미터 | 예시 | 설명 |
| --- | --: | --- |
| Roll (X축) | `180°` | 카메라 방향입니다. 기본 수직 설치의 예시입니다. |
| Pitch (Y축) | `90°` | 카메라 방향입니다. 기본 수직 설치의 예시입니다. |
| Yaw (Z축) | `90°` | 카메라 방향입니다. |
| X 위치 | `430 mm` | 차량의 전후 축을 따른 카메라 위치입니다. |
| Y 위치 | `0 mm` | 차량의 좌우 축을 따른 카메라 위치입니다. `0`은 중앙을 의미합니다. |
| Z 위치 | `120 mm` | 지면에서 카메라까지의 높이입니다. |

먼저 장착 높이를 설정한 다음 포인트 클라우드 보기에서 지면이 수평이 될 때까지 roll과 pitch를 미세 조정하세요. 완료되면 **Send parameters**를 선택하세요.

### 장애물 회피 영역

| 파라미터 | 예시 | 용도 |
| --- | --: | --- |
| 경고 거리(먼 X) | `2000 mm` | 이 거리보다 먼 영역은 비어 있는 것으로 간주합니다. 알람 거리까지의 구간은 경고/감속 영역입니다. |
| 알람 거리(중간 X) | `1500 mm` | 차폐 거리까지의 구간은 알람/정지 영역입니다. |
| 차폐 거리(가까운 X) | `600 mm` | 근거리 끝의 사각 영역입니다. 이 영역의 장애물은 장애물 회회에서 제외됩니다. |
| 좌우 범위(Y) | `−810 / 1270 mm` | 차량 중심선 양쪽의 감지 한계입니다. |
| 하한/상한 높이(Z) | `10 / 1500 mm` | 감지에 포함되는 높이 범위입니다. |

<Tip>
  X 값은 차량 중심을 기준으로 합니다. 실제 보호 거리에는 카메라의 X 오프셋도 반영해야 하며, 예를 들어 경고 거리에서 카메라의 전후 오프셋을 빼야 합니다.
</Tip>

지원되는 영역 그룹 수는 전환 방식에 따라 다릅니다.

| 전환 방식 | 지원 그룹 |
| --- | --: |
| S2 / S2 Max 2.0 I/O | `0–3` |
| SDK, UDP, RS485, or CAN | `0–19` (모델에 따라 다름) |

검증된 값을 `Tools\\params\\<camera ID>\\avoidance.json`에 백업하세요. **Load configuration from file**을 사용하여 같은 유형의 다른 차량에 이 파일을 적용할 수 있습니다.

## 통신 및 상태 출력

필드버스 또는 네트워크 프로토콜을 사용하기 전에 호스트 애플리케이션에서 장애물 회피 영역과 외부 파라미터를 구성하세요. API를 제외한 대부분의 통신 방식은 파라미터 그룹을 전환하므로 자세한 파라미터 설정에는 호스트 애플리케이션 또는 API를 사용하세요.

| Camera | 지원 통신 |
| --- | --- |
| S2 | API, UDP, I/O |
| S2 Max | API, UDP, CAN |
| S2 Max 2.0 | API, UDP, I/O, CAN |
| M4 Pro | API, UDP, RS485 |
| M4 | API, UDP, CAN |
| M4 Mega | API, UDP, I/O, CAN |

<Note>
  I/O의 우선순위가 가장 높습니다. I/O가 활성화된 동안 다른 방식은 현재 파라미터 그룹을 변경할 수 없지만 기본 또는 임시 파라미터는 업데이트할 수 있습니다. 호스트 애플리케이션과 API는 기본 파라미터를 설정하고 UDP, CAN 및 RS485는 일반적으로 임시 파라미터를 설정합니다. 전원 손실 후 동작은 최신 구성을 저장한 방식에 따라 달라집니다.
</Note>

### API

Windows, Linux 및 ARM 애플리케이션은 SDK를 통해 장애물 회피 API를 호출할 수 있습니다. Windows 호스트 애플리케이션을 설치하면 설치 디렉터리에서 SDK와 예제를 사용할 수 있습니다. 장애물 회피 예제는 `Sample\\C\\application_obstacled`에 있습니다. S10에서는 API로 파라미터 그룹을 빠르게 전환하지 말고 UDP 또는 I/O를 사용하세요.

### RS485(M4 Pro 전용)

권장 보드레이트 `9600`으로 Modbus RTU를 사용하세요. 함수 코드 `0x04`로 주소 `108`(`0x6C`)에서 시작하는 두 입력 레지스터를 읽어 현재 장애물 회피 결과를 가져옵니다. 함수 코드 `0x06`으로 주소 `106`(`0x6A`)의 단일 레지스터에 기록하여 파라미터 그룹을 전환합니다.

| 핀 | 신호 | 전선 색상 |
| --: | --- | --- |
| 1 | GND | 파란색 |
| 2 | RS485\_A | 회색 |
| 3 | RS485\_B | 흰색 |
| 4 | VIN\+ | 갈색 |
| 5 | VIN− | 검은색 |

### UDP 및 TCP

메시지는 16진수 프레임으로 전송됩니다. UDP에서는 먼저 연결 설정 메시지를 보내세요. 연결이 설정되면 카메라는 이미지 프레임 속도로 결과를 전송합니다.

| 방향 | Frame | 의미 |
| --- | --- | --- |
| 카메라 → 컨트롤러 | `ACED0410XX000000` | 장애물 없음. `XX`는 현재 파라미터 그룹입니다. |
| 카메라 → 컨트롤러 | `ACED0410XX000001` | 경고/감속입니다. |
| 카메라 → 컨트롤러 | `ACED0410XX000002` | 알람/정지입니다. |
| 컨트롤러 → 카메라(UDP) | `ACED040000000000` | UDP 연결을 설정합니다. |
| 컨트롤러 → 카메라 | `ACED041A00000000` to `ACED041A00000013` | 파라미터 그룹 `0–19`를 전환합니다. |
| 컨트롤러 → 카메라 | `ACED041B00000000` | 현재 그룹을 기본 그룹으로 저장합니다. |

기본 원격 UDP 포트는 `6688`입니다. 파라미터를 전환하려면 로드 시간이 필요하므로 빠르게 전환하지 마세요. 이미지 프레임 속도와 결과 갱신 속도가 낮아질 수 있습니다.

### CAN 및 I/O

지원 모델에서는 CAN으로 파라미터 그룹을 전환할 수 있습니다. I/O 출력은 통과, 감속 및 비상 정지 상태를 보고합니다. 출력 유형은 push-pull 또는 open-drain일 수 있으므로 배선하기 전에 컨트롤러 입력 유형을 확인하세요.

| Push-pull OUT1 | Push-pull OUT2 | 상태 |
| --- | --- | --- |
| `24 V` | `24 V` | 장애물 없음 |
| `24 V` | `0 V` | 감속 |
| `0 V` | `24 V` | 비상 정지 |
| `0 V` | `0 V` | 비활성화, 초기화 중 또는 오류 |

<Warning>
  S10에서는 `24 V−`를 컨트롤러 전원 접지에 연결하고 `IN_G` 및 `OUT_G`를 컨트롤러 신호 접지에 연결하세요. 컨트롤러가 두 접지를 구분하지 않으면 현장에서 승인된 공통 접지 방식을 사용하세요. 컨트롤러가 PNP 또는 NPN 신호를 사용하는지 확인하고 멀티미터로 배선을 검증하세요.
</Warning>

## 문제 해결

| 증상 | 확인 사항 |
| --- | --- |
| 검은색 or low-reflectivity objects are missed | 포인트 클라우드 범위를 확인하고 적분 시간과 낮은 신호 임계값을 조정하세요. 필요한 경우 검은색 포크 끝에 반사면을 추가하세요. |
| 낮은 객체가 감지를 트리거하지 않음 | Z 하한을 확인하고 검증을 위해 일시적으로 `0`으로 설정하세요. 그래도 감지에 실패하면 장착 높이와 포인트 클라우드 범위를 확인하세요. |
| 파라미터s do not take effect | 파라미터가 전송되었는지 확인하세요. 파라미터 유효성, 네트워크 연결 및 파라미터 그룹 우선순위를 확인하세요. |
| 비정상 데이터 | 장착 구조물의 장애물, 렌즈 보호 필름 또는 추가 보호 유리가 있는지 확인하세요. |
