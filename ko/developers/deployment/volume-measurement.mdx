체적 측정 알고리즘은 카메라에서 실행되며 정지 또는 이동 객체의 길이, 너비 및 높이를 측정합니다. 배포에는 견고한 설치, 네트워크 연결, 외부 파라미터 캘리브레이션 및 감지 영역 구성이 필요합니다. 여러 카메라를 기가비트 스위치를 통해 같은 네트워크에 연결하세요.

<Info>
  이 페이지는 숨겨진 과거 배포 가이드입니다. 알고리즘 펌웨어와 전용 호스트 애플리케이션은 프로젝트별로 제공됩니다. 배포 전에 카메라, 펌웨어 및 소프트웨어 버전이 일치하는지 확인하세요.
</Info>

## 범위

이 절차는 M Series 카메라를 사용하는 물류, 소포, 창고 및 벌크 자재 체적 측정 프로젝트에 적용됩니다. 알고리즘은 감지 영역의 하나 이상의 객체를 측정합니다. 객체 식별, 중량 수집 및 비즈니스 시스템 연동은 상위 시스템에서 처리합니다.

제품 정보는 [M Series ToF 카메라](/ko/products/m-series/overview "M Series ToF cameras")를 참조하세요.

## 설치 및 시스템 준비

### 하드웨어 설치

- 견고한 브래킷을 사용하여 M4 카메라 전면이 감지 평면과 평행하고 감지 평면을 향하도록 장착하세요.
- 카메라에 `24 VDC` 전원을 공급하세요. Cat6A 또는 Cat7 케이블로 카메라를 호스트 또는 기가비트 스위치에 연결합니다.
- 여러 카메라를 사용하는 경우 각 카메라에 고유한 네트워크 주소를 할당하고 전원 상태를 확인하세요.

<Frame>
  ![체적 측정을 위해 아래쪽을 향해 설치한 M4 카메라](/images/developers/deployment-volume-measurement-camera-installation-methods.avif)
</Frame>

### 호스트 요구 사항

| Item | 권장 구성 |
| --- | --- |
| Operating system | Windows 10 or later |
| CPU | Intel® Core™ i5 (7th generation) or later |
| Memory | 8 GB or more |
| GPU | Intel® UHD Graphics or a higher-performance integrated or discrete GPU |

먼저 [LxCameraViewer](/ko/developers/software/lxcameraviewer "Software download")를 설치한 다음 프로젝트에서 제공한 체적 측정 애플리케이션을 `Lanxin-MRDVS\\Tools` 디렉터리에 넣으세요. 제공 지침에 따라 파일을 교체합니다.

<Warning>
  펌웨어 업그레이드 중 카메라가 재시작됩니다. 프로젝트에서 제공한 알고리즘 패키지만 사용하고 업그레이드 전에 검증된 구성을 백업하세요.
</Warning>

## 배포 절차

### 1. 네트워크 구성

호스트와 카메라를 같은 서브넷에 연결하세요. 원래 배포 예제에서는 다음을 사용합니다.

| Item | Example |
| --- | --- |
| 호스트 IP | `192.168.100.xxx` |
| Subnet mask | `255.255.255.0` |
| Default gateway | `192.168.100.1` |

Windows Ethernet 어댑터 속성에서 **Internet Protocol Version 4 (TCP/IPv4)**를 선택하고 고정 주소를 설정하세요. 디버깅 네트워크의 방화벽 규칙에서 애플리케이션을 허용하고 프로덕션 방화벽을 영구적으로 비활성화하지 마세요.

### 2. 외부 파라미터 캘리브레이션

<Steps>
  <Step title="캘리브레이션 상태 복원">
    **카메라 구성**을 여세요. `x`, `y`, `z`, `roll`, `pitch`, `yaw`가 `0`인지 확인하세요. 기존 값이 있으면 초기화하고 **Save and send**를 선택합니다.
  </Step>
  <Step title="캘리브레이션 실행">
    **Extrinsic calibration**을 선택하고 성공 메시지를 확인한 뒤 결과 `z` 값을 기록하세요.
  </Step>
  <Step title="포즈 파라미터 저장">
    `z`를 다시 `0`으로 설정하고 **Save and send**를 선택하세요. 이 절차에서는 실제 카메라 높이가 다음 단계의 감지 평면 거리로 사용됩니다.
  </Step>
</Steps>

### 3. 감지 평면 및 영역 설정

**Volume detection**에서 기록한 `z` 값을 **감지 평면 거리**로 입력한 다음 저장하고 전송하세요. 포인트 클라우드 보기에서 감지 영역 경계를 구성합니다.

| 파라미터 | 의미 |
| --- | --- |
| Minimum / maximum X | 감지 박스의 X 경계 |
| Minimum / maximum Y | 감지 박스의 Y 경계 |
| Minimum / maximum Z | 감지 박스의 Z 경계 |

감지 평면 거리는 바닥 기준을 정의하므로 Z 상한을 이 거리보다 약간 높게 설정하세요. 하한은 측정할 객체 높이를 포함해야 합니다. 구성 후 **Save and send**를 선택합니다.

### 4. 결과 확인

**Basic tools**에서 체적 상태를 확인하세요. 감지 영역에 객체를 놓고 개수와 길이, 너비, 높이가 현장 조건과 일치하는지 확인합니다. 여러 객체가 있으면 체적 박스를 전환하여 각 결과를 확인하세요.

단일 촬영 측정에서는 **Volume detection**의 **트리거 모드**를 활성화하고 구성을 저장한 다음 **Basic tools**에서 **Single trigger**를 선택하여 한 프레임과 결과를 수집하세요.

## 주요 인터페이스 및 파라미터

### 체적 감지 파라미터

| 파라미터 | 설명 |
| --- | --- |
| 트리거 모드 | 활성화하면 알고리즘은 트리거 후에만 결과를 출력합니다. |
| Upward detection | 감지 방향을 반전합니다. 기본 절차에서는 아래쪽을 감지합니다. |
| Detection frequency | 이미지 및 결과 갱신 주기입니다. |
| 감지 평면 거리 | 카메라에서 감지 평면까지의 거리이며 단위는 `mm`입니다. |
| Neighborhood count / distance threshold | 포인트 클라우드 필터링 파라미터이며 대부분의 경우 프로젝트 기본값을 유지하세요. |
| Normal-vector filter / distance threshold | 가장자리 및 포인트 클라우드 필터링 파라미터이며 변경하기 전에 원래 구성을 보존하세요. |
| 최소 포인트 수 | 유효한 객체로 인정하기 위한 최소 포인트 수입니다. |
| Minimum X / Y / Z | 감지 가능한 객체의 최소 크기이며 단위는 `mm`입니다. |

### 카메라 구성

| Item | 설명 |
| --- | --- |
| Camera name | 여러 카메라를 배포한 환경에서 카메라를 구분합니다. |
| Image-save mode | 알고리즘 이미지를 카메라에 저장합니다. |
| Image-acquisition mode | `MDS`는 카메라 액세스를 점유하지 않습니다. `SDK`는 점유하므로 실행 중인 호스트 애플리케이션에서 카메라를 열 수 없습니다. |
| Extrinsics | `x`, `y`, `z`, `roll`, `pitch`, `yaw`입니다. |
| Save and send | 현재 외부 파라미터와 알고리즘 구성을 카메라에 기록합니다. |

## 결과 인터페이스

TCP, UDP 및 HTTP는 `RESULT_UPDATE` 명령으로 체적 결과를 요청합니다.

| Protocol | Port | 용도 |
| --- | --: | --- |
| TCP | `14951` | 체적 감지 결과 요청 |
| UDP | `14950` | 체적 감지 결과 요청 |
| HTTP | `14952` | 체적 결과를 JSON으로 요청 |

<ParamField body="command" default="RESULT_UPDATE" type="string" required>
  카메라에 현재 체적 감지 결과를 요청합니다.
</ParamField>

HTTP 최상위 응답 필드:

<ResponseField name="IP" type="string" required>
  데이터를 생성한 카메라의 IP 주소입니다.
</ResponseField>

<ResponseField name="TM" type="object[]" required>
  감지된 객체 목록입니다.
</ResponseField>

<ResponseField name="TM_DATA_TIME" type="string">
  체적 데이터가 캡처된 시간입니다.
</ResponseField>

<ResponseField name="TM_RES_TIME" type="string">
  결과가 출력된 시간입니다.
</ResponseField>

<ResponseField name="nick_name" type="string">
  카메라 이름입니다.
</ResponseField>

<ResponseField name="ret_code" type="integer" required>
  반환 코드이며 `0`은 성공을 나타냅니다.
</ResponseField>

각 `TM` 객체에는 다음 필드가 포함될 수 있습니다.

<ResponseField name="angle" type="number">
  객체 박스 각도입니다.
</ResponseField>

<ResponseField name="cx" type="number">
  객체 중심 X 좌표입니다.
</ResponseField>

<ResponseField name="cy" type="number">
  객체 중심 Y 좌표입니다.
</ResponseField>

<ResponseField name="cz" type="number">
  객체 중심 Z 좌표입니다.
</ResponseField>

<ResponseField name="height" type="number">
  객체 높이입니다.
</ResponseField>

<ResponseField name="length" type="number">
  객체 길이입니다.
</ResponseField>

<ResponseField name="width" type="number">
  객체 너비입니다.
</ResponseField>

<ResponseField name="valid" type="boolean">
  결과가 유효한지 나타냅니다. `false`는 신뢰도가 부족함을 의미합니다.
</ResponseField>

## 문제 해결

| 증상 | 권장 조치 |
| --- | --- |
| 포인트 클라우드 보기가 비어 있거나 확인하기 어려움 | 포인트 클라우드 영역에서 스크롤하고 드래그하여 카메라가 데이터를 출력하는지 확인하세요. |
| 캘리브레이션 후 감지가 비정상임 | 외부 파라미터 `z`가 `0`으로 재설정되었고 기록한 캘리브레이션 높이가 감지 평면 거리로 입력되었는지 확인하세요. |
| 객체가 감지되지 않음 | 영역 경계, 최소 크기, 최소 포인트 수 및 객체가 시야에 완전히 들어오는지 확인하세요. |
| LxCameraViewer를 열 수 없음 | `SDK` 이미지 수집 모드가 선택되어 있는지 확인하세요. 이 모드는 카메라 액세스를 점유합니다. |
